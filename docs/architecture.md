## 技术选型

| 层 | 技术 | 选型理由 |
|----|------|----------|
| 前端框架 | React 18 + CRA | 组件化开发，生态丰富，适合电商交互场景 |
| 前端路由 | React Router 6 | 声明式路由，支持嵌套路由和动态参数 |
| 后端框架 | Express 4 | 轻量灵活，中间件机制适合 RESTful API |
| 数据库 | SQLite (better-sqlite3) | 零配置、单文件部署、同步 API 简化事务 |
| 认证 | JWT + bcryptjs | 无状态认证，跨服务友好；bcrypt 防暴力破解 |
| 文件上传 | Multer | Express 生态标准方案，支持磁盘存储和过滤 |

## 关键设计决策

### 1. SQLite + WAL 模式

选择 SQLite 而非 MySQL/PostgreSQL 的原因：
- 单文件部署，零运维
- better-sqlite3 提供同步 API，天然支持事务
- 开启 WAL 模式后支持并发读

### 2. JWT 无状态认证

Token 携带 `{ id, username, role }`，7 天有效期。前端存储在 `localStorage`，每次请求通过 `Authorization` 头携带。

优势：无需服务端 session 存储
权衡：无法主动失效 Token（通过前端删除 + 401 强制跳转弥补）

### 3. 订单事务一致性

下单操作在单个数据库事务中完成：
1. 检查商品状态和库存（SELECT）
2. 扣减库存、增加销量（UPDATE）
3. 创建订单和订单项（INSERT）
4. 删除购物车项（DELETE）

任何一步失败则整体回滚，避免超卖或数据不一致。

### 4. 订单状态机

```
pending ──→ paid ──→ shipped ──→ delivered
   │         │
   └──→ cancelled ←┘
```

状态只能向前流转或取消，不允许回退。取消时恢复库存和销量。

### 5. 快照模式

订单项中保存下单时的 `product_name`、`price`、`product_image`，而非仅引用 ID。这保证商品信息变更后历史订单仍然准确。

### 6. 分页安全

`sanitizePagination()` 函数确保：
- page ≥ 1
- limit ∈ [1, maxLimit]
- 避免 SQL 注入（参数化查询）

### 7. 搜索安全

`escapeLike()` 函数转义 `%`、`_`、`\` 字符，防止 LIKE 通配符注入。

## 前端架构

### 状态管理

使用 React Context 集中管理全局状态：

```
AuthContext
├── user          — 当前用户信息
├── token         — JWT Token
├── isAdmin       — 是否管理员
├── cartCount     — 购物车商品数（实时更新）
├── login()       — 登录
├── logout()      — 退出
└── refreshCartCount() — 刷新购物车数量
```

各页面内部状态使用 `useState` + `useEffect` 管理，无额外状态库。

### API 封装

`utils/api.js` 统一处理：
- 自动注入 Token
- 401 自动跳转登录页
- 统一错误提示

### 组件复用

| 组件 | 用途 |
|------|------|
| Navbar | 全局导航，含搜索框、购物车角标、移动端菜单 |
| Pagination | 分页控件，含首页/末页快捷跳转和省略号 |
| NotFound | 404 页面 |

## 安全措施

| 措施 | 实现方式 |
|------|----------|
| 密码存储 | bcrypt 哈希（10 轮 salt） |
| 注册限流 | 内存 Map，同一 IP 每分钟最多 3 次，5 分钟清理过期记录 |
| JWT 密钥 | 从环境变量读取，不硬编码 |
| 文件上传 | crypto.randomBytes 随机文件名，限制 5MB，白名单扩展名 |
| SQL 注入 | 参数化查询 + LIKE 通配符转义 |
| CORS | 可配置允许的 Origin，支持多域名 |
| 管理员接口 | authMiddleware + adminMiddleware 双重验证 |
